How the map works

The 3W map is a small list of goals, drivers (a rule, spec or owner review that demands something) and decisions. Each decision links up only: serves a goal (why), required by a driver (who) and triggered by an earlier decision (when). Effects are never stored; they are computed by reversing the links.

  • Per task: log the task and its effort, look up related decisions (find, why, open), add a decision node for anything new.
  • Close gate: a decision can only be marked done with a commit and a written verification. That is the main behaviour the trial tests.
  • Meter: every map call is counted in tokens, and every task's real token use, time and rounds are read from the session transcript.

Where the map was used, and whether it helped

Verdict is my own rating per task, written from what the map calls did, not from a counterfactual. Yes: it prevented rework, exposed a gap or answered a question without reading files. Neutral: it recorded something, no visible effect. No: not used or no effect.
